## 五个发现

**1. Syncline 的 tailwind.config 是一套没人用的调色板。** config 里定义了 17 个颜色（teal.coastal、clay.warm、mauve.haze…）、4 个阴影、`ease-soft`、`rounded-4xl/5xl`、`font-ui`。App.tsx 里这些 class **一个都没出现**。实际用的 22 个颜色全部是 `bg-[#54B8AB]` 这种任意值写法，其中 17 个 hex 在 App.tsx 里直接出现 189 次。这是最硬的 before 证据：有 config 不等于有系统。

**2. 网站有 74 个近中性灰。** `#62625d`、`#666662`、`#666761`、`#676761`、`#686963`、`#696965`、`#696a64`……这些是同一个"muted text"在不同地方被重新目测出来的结果。合并后大概需要 7–9 阶。

**3. 两个产品共用同一条 easing 曲线。** 网站的 `cubic-bezier(.22,1,.36,1)` 和 Syncline config 的 `soft` 完全一样。这是底座 `motion.easing.enter` 的现成候选。

**4. 网站的字号靠 38 个 clamp() 各自为政。** 每个标题都是单独调的 clamp，没有共用的字阶；固定 px 的 25 档里 7、8、9、11、12、12.5、13、14、15 挤在小字区。line-height 28 个值里没有一个是整数倍关系，基线网格不存在。

**5. Syncline 的字体被覆盖了三次。** `index.css` 说 Inter，`tailwind.config` 说 display 用 Georgia，`hig-refinements.css` 又改成 SF Pro 正文 + New York 标题。最终线上生效的是第三层。网站这边干净：Manrope / DM Mono / Newsreader 三套各有分工。

另外 `DESIGN.md` 里其实已经有"One portfolio, three project identities"和"global grid, typography, controls, spacing, and motion remain consistent; each case study receives one accent"这条原则——它就是"一个底座多个主题"的原始表述，案例里可以引用。

## 三个决定

### 决定 1 · 字体：保留网站的三套，Syncline 收成两套

| 角色 | 网站（主题 A） | Syncline（主题 B） |
| --- | --- | --- |
| body / UI | Manrope | Inter |
| display | Newsreader | New York（回退 Georgia） |
| mono / label | DM Mono | — |

砍掉：Syncline 的 SF Pro 层（hig-refinements 里的 `-apple-system` 栈）和 config 里从未用过的 `font-display: Georgia`。

理由：底座只定三个**角色**（`font.body`、`font.display`、`font.mono`），不定字体名。网站三个角色都用，Syncline 用两个。SF Pro 是嵌入时为了"像原生"打的补丁，但它和 Inter 在正文尺寸几乎分不出来，留一个就够；New York 保留是因为它和 Newsreader 一样承担了 display 的"编辑感"，两个主题在 display 角色上的用法一致。

### 决定 2 · 近似色合并：按角色收，不按色值收

不逐个比对 74 个灰哪两个"够近"，而是先定角色再回填：

| 角色 | 网站当前最常用的值 | Syncline 当前最常用的值 |
| --- | --- | --- |
| `fg.primary` | `#121310`（--ink，34 次） | `#1f1f1f`（27 次） |
| `fg.secondary` | `#62625d`（--muted） | `#3a3a3a` |
| `fg.muted` | `#8a8982` / `#9e9e99` 一带 | — |
| `bg.canvas` | `#f3f1ec`（--paper） | `#f7f4ef`（24 次） |
| `bg.raised` | `#f8f6f1` | `#f7f0e6` |
| `border.subtle` | `#cbc8bf`（--rule） | `#e8e0d6` |
| `action.primary` | 按页面切换的 accent | `#54b8ab`（36 次） |
| `focus.ring` | — | `#1f7a77`（和 `#1d7f7a`、`#167f79` 三个值合并成这一个） |

其余 60 多个灰：凡是 fg/bg/border 角色能覆盖的，统一换成角色变量；覆盖不了的（aurora 渐变、mask）保留为该页面主题层里的 `scene.*` 局部值，不进底座。

理由：盘点表证明这些灰是"重复目测"而不是"刻意的细微差别"，所以按角色收损失很小；而按色值距离合并会留下一堆没有语义的 `grey-62`、`grey-66`。

### 决定 3 · neutral 色阶：共用一组暖灰底座，两个主题只改 accent

两个产品的中性色在同一条色相上：网站 `#f3f1ec` → `#121310`，Syncline `#f7f4ef` → `#1f1f1f`，都是微偏暖的米白到近黑。差异小于两个产品内部各自的噪音。

所以底座的 `neutral` 色阶（约 10 阶）两个主题**共用**，主题层只覆盖 `bg.canvas` 的具体阶和 `accent` 色族。Syncline 的 teal / lavender / sand / gold 六色，以及网站按页面切换的 acid / violet / orange / signal，全部属于主题层的 accent。

理由：共用 neutral 是"一个底座两个主题"能成立的关键证据——如果连灰都要各一套，底座就只剩间距和动效了。而且共用后 Syncline 嵌在网站里时，边界会更自然。
