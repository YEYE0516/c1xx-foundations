# Day 3 · 间距、圆角、层级、动效

产出 `foundations/spacing.json`、`shape.json`、`motion.json`。每一项都对着盘点里的 before 数字收。

## 间距：63 个值 → 10 档 + 6 档版面间距

| token | 值 | 用在 |
| --- | --- | --- |
| space.1 | 4 | 图标和文字之间 |
| space.2 | 8 | chip 内边距 |
| space.3 | 12 | 按钮上下内边距、列表间隙 |
| space.4 | 16 | 默认内边距、手机页边距 |
| space.5 | 20 | 按钮左右内边距 |
| space.6 | 24 | = 行距。卡片内边距、栅格 gap |
| space.8 | 32 | 大卡片、sheet 内边距 |
| space.10 | 40 | |
| space.12 | 48 | = rhythm.2。组件间距和版面间距的分界 |

命名用数字（4 的倍数），`space.4` 就是 16px，以后加档不用想新形容词。48 以上全部归 `rhythm.*`（昨天定的整行间距：24 / 48 / 72 / 96 / 144 / 192）。

盘点里最常用的 18px（18 次）吸附到 16，10px（14 次）吸附到 12，100px（14 次）吸附到 96。吸附表写在 `spacing.json` 的 `snap` 里，Day 5 换值的时候照表查。

另外定了控件高度：32 / 40 / 48，触控最小 44。

## 圆角：21 个值 → 5 档 + full

4 / 8 / 16 / 24 / 32 / full。比计划的"3 档"多两档，因为 Syncline 的卡片真的需要 20–34 这一段（它是手机 app，圆角比网站大是对的）；但 20、28、34 这些中间值收掉，就近吸附到 16、24、32。`999px` 和 `50%` 统一成 `full`。

## 阴影：29 个值 → 3 级 + 1 个 inset 描边

| 级 | 几何 | 用在 |
| --- | --- | --- |
| elevation.1 | 0 1 2 + 0 4 12 | 静止卡片、chip |
| elevation.2 | 0 12 28 | hover、浮动控件、bottom sheet |
| elevation.3 | 0 32 80 | 弹层、设备框、项目封面 |

关键决定：**阴影只定几何，不定颜色**。颜色引用 `color.shadow.*`，明天在颜色里定；网站用暖黑，Syncline 用它的海军蓝 `#152a55`，两个主题的阴影看起来各是各的，几何却同一套。这也是 Syncline 13 个 `shadow-[…]` 任意值能收掉的原因——它们只是同一个蓝在不同透明度。

## 动效：16 个时长 → 4 档；easing 2 条 → 3 条 + linear

| token | 值 | 替换 |
| --- | --- | --- |
| duration.fast | 120ms | 200–250 |
| duration.base | 200ms | 300–350（网站最常用，17 次） |
| duration.slow | 320ms | 450–650 |
| duration.scene | 600ms | 800–1200 |

easing.enter = `cubic-bezier(.22, 1, .36, 1)`——盘点发现两个产品已经在用同一条曲线，直接提升为底座。另加 exit（加速离场）、standard（原地移动）、linear（进度条和环境漂移）。

`reduced` 定了 `prefers-reduced-motion` 的规则：时长归 1ms，去掉 transform 类位移，保留 opacity 和颜色过渡。网站现在 aurora 的 14–17s 环境动画不进底座，归网站主题层。

`gsap` 节点把同样的值换成秒，以后 GSAP 直接读，避免两边漂移。

## 检查

- 所有间距、圆角、控件高度都是 4 的倍数 ✓
- 所有阴影颜色都是引用，没有裸 rgba ✓
- 所有时长 ≤ 600ms，环境动画不在底座 ✓
- 色块内文字缩进（昨天清单第 6 条）：组件层用 `space.4` 起步，不允许 0 ✓
